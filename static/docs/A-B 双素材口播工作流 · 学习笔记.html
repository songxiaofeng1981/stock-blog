A/B 双素材口播工作流

以后拍口播,不在拍摄阶段完成视频:只拍一条完整「讲述」(A)+ 一条或多条「视觉素材」(B)。Codex 理解两边内容并建立对应关系,PySceneDetect 拆镜头,WhisperX 定位口播,Remotion 把 B-roll 用不同动态版式插入,最后加音乐成片。

核心:只有两类素材

拍摄阶段极简 —— 口播归口播,素材归素材。

A 视频 · Talking Head

主视频(叙事主轴)

坐在电脑前对着镜头完整讲述,依次介绍第一盆、第二盆、第三盆。提供人像、声音和完整叙事。

B 视频 · B-roll Reel

素材视频(视觉补充)

不用边讲边拍。专门拍:第一盆几秒→暂停→第二盆→暂停→第三盆。得到一条含多个独立镜头的素材。

四件套:各管一件事

三个处理能力 + 一个总控。记住每个「只负责什么」,不要混。

PySceneDetect拆素材 —— B 视频里有哪些独立镜头?
输入 B 视频 → 输出 Scene 01 / 02 / 03
例:15 秒 B-roll → 第一盆 / 第二盆 / 第三盆。它不管你说了什么,也不管最终放哪。
WhisperX定位口播 —— A 视频什么时候讲到哪盆?
输入 A 视频 → 输出 文字 + 时间戳
例:12.3s「第一盆是…」/ 25.7s「第二盆是…」/ 39.1s「第三盆…」。把语言变成可剪辑的时间数据。
Remotion决定怎么呈现 —— B-roll 插进来画面长啥样
输入 broll_plan → 输出 布局 + 动画 + 文字
不是简单特效插件,而是你的「程序化视频导演 + 版式系统」,以后能固化成个人风格。
Codex总控 —— 不是第四种媒体能力,是指挥
调度:PySceneDetect · WhisperX · 建立 Scene 对应 · 生成 broll_plan · 调 Remotion · 调 FFmpeg · 输出成片
你最终只需对它说:用 A 当主视频、B 当 B-roll,自动拆 B、分析 A,讲到对应花时插入对应 B-roll,用我的 Remotion 风格组件,最后加背景音乐。

完整流程

两条输入并行处理 → 匹配 → 计划 → 呈现 → 成片。

Remotion 版式库(个人风格可固化)

同一段 B-roll,换版式就换观感 —— 这层积累起来就是你的导演语言。

Fullscreen 全屏出现(第一盆)
右侧 1/3 占屏一角(第二盆)
Split 50 半屏分割(第三盆)
Zoom 放大强调重点细节
PiP 画中画补充画面
Floating Card 卡片滑入(产品截图)
Push 推入切换
Freeze + Callout 定格 + 标注

核心洞察:拍摄与剪辑解耦

这是今天真正想通的一点 —— 注意力被拆开,每个阶段只做一件事。

1

只负责讲

口播阶段:只管讲清楚,不想镜头/特效。

2

只负责拍素材

B-roll 阶段:只管拍好看。

3

机器负责组合

Codex + Remotion 重新组装。

⭐ 为什么对你(观点 / 解释 / 财经技术类内容)特别合适

以前拍视频要同时想「说什么 + 要不要拍花 + 怎么插 + 镜头够不够 + 要不要重拍」,全混在一起。现在三段解耦,每段心智负担骤降。

「三盆花」只是最小模型

题材换了,生产方法不用换 —— 结构完全一样。

同一结构可复用于:三个显示器 / 三个锅 / 三款手机 / 三个股票 App / 三张财报 / 三家公司 / 三个数据中心镜头……
甚至一条 10 分钟财经口播:A = 你讲 10 分钟;B = GPU / HBM / 数据中心 / 晶圆厂 / 黄仁勋 / 财报截图 / 股票走势图 / 产品照片。还是同一个结构。

复习自测(先盖住答案自己答)

能顺畅答出这 5 条,这套工作流就记牢了。

  • A 视频和 B 视频各自只负责什么?为什么要分开拍?
  • PySceneDetect、WhisperX 各自的输入和输出是什么?谁管「镜头」,谁管「时间」?
  • Codex 为什么不是「第四种媒体处理能力」?它的真实角色是什么?
  • Remotion 为什么说它更像「导演/版式系统」而不是「特效插件」?举 3 个版式。
  • 把整套工作流从输入到成片的流程,用一句话复述出来。
